1. Introduction

Note📊 Understanding Risk in Modern Finance

1.1 Risk in Portfolio Management

Risk is the fundamental uncertainty associated with future investment outcomes. In portfolio management, risk represents the potential deviation of actual returns from expected returns, with particular concern for adverse outcomes that result in financial losses. Unlike simple volatility measures that treat upside and downside deviations equally, modern risk management focuses on downside risk—the probability and magnitude of losses below a certain threshold.

ImportantWhy Variance Is Not Enough

Traditional portfolio theory, pioneered by Markowitz, uses variance as a symmetric risk measure. However, variance fails to distinguish between gains and losses, treating both as equally undesirable deviations. In practice, investors are primarily concerned with losses, not gains. This asymmetric perspective motivates the use of downside risk measures such as VaR and CVaR.

1.2 Value-at-Risk (VaR)

Tip💡 What is VaR?

Value-at-Risk answers a simple but powerful question: “What is the maximum loss we can expect with a given confidence level?”

For example, a 99% VaR of $1,000 means there is only a 1% chance that the portfolio will lose more than $1,000.

Value-at-Risk is a quantile-based risk measure that estimates the maximum expected loss over a given confidence level. If \(R_P\) denotes portfolio return and \(L_P = -R_P\) the loss, then the VaR at confidence level \(\alpha\) is formally defined as:

\[\text{VaR}_\alpha = \inf\{l: P(L_P > l) \leq 1-\alpha\}\]

For example, a one-day 99% VaR of $1,000 means there is only a 1% chance that the portfolio will lose more than $1,000 in one day. VaR has become the industry standard for risk reporting, mandated by regulatory frameworks such as Basel III for banks.

1.3 Conditional Value-at-Risk (CVaR)

Warning⚠️ VaR’s Limitation: The Tail Beyond the Threshold

While VaR provides a threshold for losses, it does not describe the magnitude of losses beyond that threshold. This is where CVaR becomes critical.

CVaR measures the expected loss given that losses exceed the VaR threshold, providing crucial information about extreme tail events.

Conditional Value-at-Risk, also known as Expected Shortfall, addresses VaR’s limitation by measuring the expected loss given that losses exceed the VaR threshold:

\[\text{CVaR}_\alpha = \mathbb{E}[L_P \mid L_P > \text{VaR}_\alpha]\]

CVaR is superior to VaR in several respects: it is a coherent risk measure (satisfying subadditivity), it is more sensitive to tail risk, and it provides information about the severity of extreme losses. CVaR is increasingly preferred in optimization and risk management applications.

1.4 Methodological Approaches

Note🔬 Three Approaches to Measuring Risk

This project employs three distinct methodologies, each with different assumptions and trade-offs:

  1. Parametric Method - Fast but assumes normality
  2. Historical Simulation - Non-parametric but backward-looking
  3. Monte Carlo Simulation - Flexible but computationally intensive

This project employs three distinct approaches to estimate VaR and CVaR:

Parametric (Variance-Covariance) Method: Assumes portfolio returns follow a normal distribution with parameters estimated from historical data. VaR and CVaR are computed analytically using the mean and standard deviation of returns. This method is computationally efficient but relies heavily on the normality assumption, which often fails during market stress.

Historical Simulation: Uses the empirical distribution of historical returns without imposing distributional assumptions. VaR is the empirical quantile, and CVaR is the average of losses beyond VaR. This method is non-parametric and captures actual historical patterns, but it assumes the future will resemble the past and is limited by available data.

Monte Carlo Simulation: Generates synthetic return scenarios by sampling from a multivariate normal distribution calibrated to historical mean and covariance. This method explicitly models correlations between assets and can incorporate complex dependencies, but it still assumes normality and requires careful calibration.

4. Portfolio Construction via Efficient Frontier

4.1 Modern Portfolio Theory and the Efficient Frontier

Note📈 The Efficient Frontier Concept

The efficient frontier represents the set of portfolios that offer the maximum expected return for a given level of risk (or minimum risk for a given return level).

Key Insight: No rational investor should hold a portfolio below the efficient frontier—such portfolios are dominated by efficient portfolios offering either: - Higher return for the same risk, or - Lower risk for the same return

Modern Portfolio Theory, developed by Harry Markowitz, recognizes that portfolio risk depends not only on individual asset volatilities but also on correlations between assets. By combining assets with less-than-perfect correlation, investors can reduce portfolio variance without sacrificing expected return.

The expected return of a portfolio with weights \(w\) is:

\[\mu_P = w^\top \mu\]

where \(\mu\) is the vector of expected returns. The portfolio variance is:

\[\sigma_P^2 = w^\top \Sigma w\]

where \(\Sigma\) is the covariance matrix of returns.

The efficient frontier is the upper boundary of the feasible region in mean-variance space, representing portfolios that maximize return for each level of risk.

4.3 Efficient Frontier Construction

Tip🎯 Building the Efficient Frontier

To construct the efficient frontier, we solve a series of optimization problems:

\[\min_w \quad w^\top \Sigma w\] \[\text{subject to} \quad w^\top \mu = \mu_{\text{target}}, \quad \sum_{i=1}^{n} w_i = 1, \quad w_i \geq 0\]

By varying \(\mu_{\text{target}}\) from minimum to maximum feasible return, we trace out the entire efficient frontier.

We construct the efficient frontier by solving for the minimum-variance portfolio at different target return levels:

def portfolio_metrics(weights, mu, Sigma):
    """Calculate portfolio return and volatility"""
    port_return = weights @ mu
    port_volatility = np.sqrt(weights @ Sigma @ weights)
    return port_return, port_volatility

def optimize_for_return(target_return, mu, Sigma):
    """Find minimum variance portfolio for a target return"""
    n_assets = len(mu)
    
    # Initial guess
    w0 = np.ones(n_assets) / n_assets
    
    # Constraints
    constraints = [
        {'type': 'eq', 'fun': lambda w: np.sum(w) - 1},  # weights sum to 1
        {'type': 'eq', 'fun': lambda w: w @ mu - target_return}  # target return
    ]
    
    # Bounds: long only
    bounds = tuple((0, 1) for _ in range(n_assets))
    
    # Objective: minimize variance
    def portfolio_variance(w):
        return w @ Sigma @ w
    
    result = minimize(
        portfolio_variance,
        w0,
        method='SLSQP',
        bounds=bounds,
        constraints=constraints,
        options={'ftol': 1e-9, 'maxiter': 1000}
    )
    
    return result

# Find minimum and maximum returns
min_var_result = minimize(
    lambda w: w @ Sigma @ w,
    np.ones(len(mu)) / len(mu),
    method='SLSQP',
    bounds=tuple((0, 1) for _ in range(len(mu))),
    constraints={'type': 'eq', 'fun': lambda w: np.sum(w) - 1},
    options={'ftol': 1e-9}
)

min_return = min_var_result.x @ mu
max_return = mu.max()

# Generate efficient frontier
n_portfolios = 100
target_returns = np.linspace(min_return, max_return * 0.95, n_portfolios)
efficient_portfolios = []

for target_ret in target_returns:
    result = optimize_for_return(target_ret, mu.values, Sigma.values)
    if result.success:
        ret, vol = portfolio_metrics(result.x, mu.values, Sigma.values)
        efficient_portfolios.append({
            'return': ret,
            'volatility': vol,
            'weights': result.x
        })

# Convert to DataFrame

4.5 Selecting an Optimal Portfolio

Important🎲 Portfolio Selection Strategy

We select a portfolio from the efficient frontier that balances risk and return. Rather than choosing the minimum-variance portfolio (too conservative) or maximum-return portfolio (too risky), we select a portfolio with:

  • Moderate expected return: Adjustable to ensure valid VaR/CVaR estimates
  • Acceptable volatility: Offering meaningful diversification benefits
  • Balanced risk profile: Suitable for a moderately risk-averse investor

Important: If expected return is too high relative to volatility, the parametric VaR/CVaR may become negative (invalid). Adjust the selection to find a portfolio with reasonable risk metrics.

Tip🎛️ Adjustable Portfolio Selection

You can adjust the target return percentile below. Lower values (e.g., 30-40%) select more conservative portfolios with lower expected returns, which helps ensure valid parametric VaR/CVaR estimates. Higher values (e.g., 60-80%) select more aggressive portfolios with higher expected returns.

Rule of thumb: If parametric CVaR appears positive or invalid, reduce the percentile to select a more conservative portfolio.

6. Parametric (Variance-Covariance) VaR and CVaR

6.1 Normality Assumption

Note📊 Parametric Approach: Normal Distribution Assumption

Under the parametric approach, portfolio returns are assumed to follow a normal distribution and portfolio losses \(L_P = -R_P\) follow:

\[R_P \sim \mathcal{N}(-\mu_P, \sigma_P^2)\]

where \(\mu_P\) and \(\sigma_P\) represent the empirical mean and standard deviation of daily portfolio returns estimated from historical data.

The parametric method assumes portfolio returns follow a normal distribution. Under this assumption, we can compute VaR analytically using quantiles of the standard normal distribution.

6.2 VaR Calculation

Important📉 Value-at-Risk Definition

Risk is measured in terms of portfolio losses, defined as \(L_P = -R_P\). Value-at-Risk (VaR) at confidence level \(\alpha\) is the loss threshold that is exceeded with probability \(1-\alpha\).

Using the normal distribution, VaR can be expressed analytically as:

\[\text{VaR}_\alpha = -(\mu_P + z_{1-\alpha} \sigma_P)\]

where \(z_{1-\alpha} = \Phi^{-1}(1-\alpha)\) denotes the lower-tail quantile of the standard normal distribution.

Interpretation: VaR represents the worst expected loss under normal market conditions, excluding extreme tail events.

For 95% confidence, \(z_{0.05} = \Phi^{-1}(0.05) \approx -1.645\), and for 99% confidence, \(z_{0.01} = \Phi^{-1}(0.01) \approx -2.326\).

6.3 CVaR Calculation

Warning📊 Conditional Value-at-Risk (Expected Shortfall)

While VaR provides a quantile-based measure of downside risk, it does not convey information about the magnitude of losses beyond the VaR threshold. To address this limitation, Conditional Value-at-Risk (CVaR), also known as Expected Shortfall, is employed.

CVaR measures the expected loss given that the loss exceeds the VaR level. For normally distributed returns, CVaR admits a closed-form expression:

\[\text{CVaR}_\alpha = -\left(\mu_P - \frac{\sigma_P \cdot \phi(z_{1-\alpha})}{1-\alpha}\right)\]

where \(\phi(\cdot)\) denotes the standard normal probability density function.

Key Insight: Since CVaR averages losses in the tail of the distribution, it is always greater than VaR and provides a more conservative assessment of downside risk.

6.4 Example Calculation

Tip📐 Numerical Example

Consider a portfolio with daily returns approximately normally distributed with mean 0.1% and standard deviation 2%. For a 99% confidence level:

\[\text{VaR}_{0.99} = -(\mu_P - z_{0.99}\sigma_P) = -(0.001 - 2.33 \times 0.02) = 0.0456\]

This means the portfolio is expected to lose at most about 4.56% of its value with 99% confidence. If the portfolio value is $1,000,000, the 99% VaR is approximately $45,600.

# Parametric VaR and CVaR calculation
def parametric_var_cvar(returns, confidence_level=0.95):
    """
    Calculate VaR and CVaR assuming normal distribution.
    
    Parameters:
    -----------
    returns : array-like
        Daily portfolio returns
    confidence_level : float
        Confidence level (e.g., 0.95 for 95%)
    
    Returns:
    --------
    var : float
        Value-at-Risk (positive loss magnitude)
    cvar : float
        Conditional Value-at-Risk (positive loss magnitude)
    """
    # Daily statistics
    mu_P = returns.mean()
    sigma_P = returns.std()
    
    # Lower-tail quantile of standard normal
    z_alpha = stats.norm.ppf(1 - confidence_level)
    
    # PDF at z_alpha
    phi_z = stats.norm.pdf(z_alpha)
    
    # VaR: worst expected loss at confidence level
    # VaR = -(mu_P + z_alpha * sigma_P)
    var = -(mu_P + z_alpha * sigma_P)
    
    # CVaR: expected loss beyond VaR threshold
    # CVaR = -(mu_P - (sigma_P * phi(z_alpha)) / (1 - alpha))
    cvar = -(mu_P - (sigma_P * phi_z) / (1 - confidence_level))
    
    return var, cvar

7. Historical Simulation VaR and CVaR

7.1 Methodology

Historical simulation makes no distributional assumptions, instead using the empirical distribution of past returns. This non-parametric approach is conceptually simple: VaR is the empirical quantile, and CVaR is the average of losses beyond VaR.

For VaR at confidence level \(\alpha\):

\[\text{VaR}_\alpha = -Q_{1-\alpha}(R_P)\]

where \(Q_{1-\alpha}\) is the \((1-\alpha)\)-empirical quantile of portfolio returns.

For CVaR:

\[\text{CVaR}_\alpha = \mathbb{E}[L_P \mid L_P > \text{VaR}_\alpha]\]

This is simply the average of all losses that are worse than (exceed) the VaR threshold.

7.2 Implementation

def historical_var_cvar(returns, confidence_level=0.95):
    """
    Calculate VaR and CVaR using historical simulation
    
    Parameters:
    -----------
    returns : array-like
        Portfolio returns
    confidence_level : float
        Confidence level (e.g., 0.95 for 95%)
    
    Returns:
    --------
    var : float
        Value-at-Risk (positive loss magnitude)
    cvar : float
        Conditional Value-at-Risk (positive loss magnitude)

    var = -np.percentile(returns, (1 - confidence_level) * 100)

    # Losses are -returns, so we find returns <= -var
    tail_returns = returns[returns <= -var]
    cvar = -tail_returns.mean()
    
    return var, cvar

8. Monte Carlo Simulation VaR and CVaR

8.1 Methodology

Monte Carlo simulation generates synthetic return scenarios by sampling from a multivariate normal distribution calibrated to historical mean and covariance:

\[\mathbf{r}^{(s)} \sim \mathcal{N}(\boldsymbol{\mu}, \boldsymbol{\Sigma})\]

The portfolio return for each scenario is:

\[R_P^{(s)} = w^\top \mathbf{r}^{(s)}\]

8.2 Role of Correlation

Important🔗 Why Correlation Matters

Asset correlations are crucial for portfolio risk. Monte Carlo simulation explicitly models these dependencies through the covariance matrix, ensuring simulated scenarios respect historical correlation patterns.

Ignoring correlations would severely misestimate portfolio risk!

8.3 Implementation

def monte_carlo_var_cvar(mu, Sigma, weights, n_simulations=100000, confidence_level=0.95):
    """
    Calculate VaR and CVaR using Monte Carlo simulation
    
    Parameters:
    -----------
    mu : array
        Mean returns vector
    Sigma : array
        Covariance matrix
    weights : array
        Portfolio weights
    n_simulations : int
        Number of scenarios to simulate
    confidence_level : float
        Confidence level (e.g., 0.95 for 95%)
    
    Returns:
    --------
    var : float
        Value-at-Risk (positive loss magnitude)
    cvar : float
        Conditional Value-at-Risk (positive loss magnitude)
    simulated_returns : array
        Simulated portfolio returns
    """
    # Generate multivariate normal samples
    np.random.seed(42)  # For reproducibility
    simulated_asset_returns = np.random.multivariate_normal(
        mu.values, Sigma.values, n_simulations
    )
    
    # Calculate portfolio returns for each scenario
    simulated_returns = simulated_asset_returns @ weights
    
    # VaR: empirical quantile of simulated distribution
    var = -np.percentile(simulated_returns, (1 - confidence_level) * 100)
    
    # CVaR: average of losses beyond VaR
    tail_returns = simulated_returns[simulated_returns <= -var]
    cvar = -tail_returns.mean()
    
    return var, cvar, simulated_returns

11. VaR Backtesting Using Kupiec Test

Note🔍 What is VaR Backtesting?

VaR backtesting validates the accuracy of risk models by comparing forecasted VaR levels against realized losses. A well-calibrated VaR model should experience violations (losses exceeding VaR) at the expected frequency.

Key Question: Do realized losses exceed the VaR at the correct frequency?

11.1 Backtesting Framework

Tip🎯 Why Test Multiple Confidence Levels?

We test VaR at four different confidence levels: 90%, 95%, 97.5%, and 99%.

Rationale: - 90%: 10% violation rate - provides more data points for testing (better statistical power) - 95%: Standard in many applications - balances conservatism and practicality - 97.5%: Middle ground - useful for identifying model behavior - 99%: Regulatory standard (Basel) - very conservative, few expected violations

Expected violations for your data (~{len(R_P)} trading days): - 90% → ~{int(len(R_P)0.10)} violations (10% rate) - 95% → ~{int(len(R_P)0.05)} violations (5% rate)
- 97.5% → ~{int(len(R_P)0.025)} violations (2.5% rate) - 99% → ~{int(len(R_P)0.01)} violations (1% rate)

Testing multiple levels helps diagnose where the model breaks down!

VaR backtesting evaluates whether the VaR model produces accurate forecasts by examining the historical pattern of VaR violations (also called exceptions). For each trading day \(t\), we define a violation indicator:

\[ I_t = \begin{cases} 1, & L_t > \widehat{\text{VaR}}_{t,\alpha} \\ 0, & \text{otherwise} \end{cases} \]

where \(L_t = -R_{P,t}\) is the realized loss and \(\widehat{\text{VaR}}_{t,\alpha}\) is the forecasted VaR at confidence level \(\alpha\).

Under a correct VaR model: \[\mathbb{P}(I_t = 1) = 1 - \alpha\]

For example, a 95% VaR should be violated approximately 5% of the time, and a 99% VaR should be violated approximately 1% of the time.

# Helper function to compute violations
def compute_var_violations(returns, var_forecast):

11.2 Kupiec Test (Likelihood Ratio Test)

Tip📊 What Does the Kupiec Test Check?

The Kupiec test (also called the Proportion of Failures test or Likelihood Ratio test) checks whether the total number of VaR violations is consistent with the confidence level using a likelihood ratio framework.

What it checks: Correct frequency of violations
What it ignores: Timing and clustering of violations

This is the standard regulatory test used in Basel frameworks.

11.2.1 Mathematical Foundation

Let: - \(T\) = number of backtesting days - \(x = \sum_{t=1}^T I_t\) = observed number of violations - Expected violations: \(\mathbb{E}[x] = (1-\alpha)T\)

Hypotheses: \[ \begin{aligned} H_0 &: \mathbb{P}(I_t=1) = 1-\alpha \quad \text{(correct coverage)} \\ H_1 &: \mathbb{P}(I_t=1) \neq 1-\alpha \quad \text{(incorrect coverage)} \end{aligned} \]

Likelihood Ratio Test Statistic:

The Kupiec test uses a likelihood ratio (LR) statistic that compares the likelihood under the null hypothesis to the likelihood under the unrestricted model:

\[ \boxed{ LR_{\text{POF}} = -2 \ln \left[ \frac{(1-\alpha)^x \alpha^{T-x}} {\left(\frac{x}{T}\right)^x \left(1-\frac{x}{T}\right)^{T-x}} \right] } \]

Where: - Numerator: likelihood assuming true violation rate is \(1-\alpha\) - Denominator: likelihood using the empirical violation rate \(\hat{p} = x/T\)

Asymptotic Distribution: Under \(H_0\), \(LR_{\text{POF}} \sim \chi^2(1)\)

Decision Rule: At significance level \(\gamma\) (typically 5%):

\[\text{Reject } H_0 \text{ if } LR_{\text{POF}} > \chi^2_{1, 1-\gamma}\]

where \(\chi^2_{1, 1-\gamma} \approx 3.84\) for \(\gamma = 0.05\).

11.2.2 Implementation and Results

def kupiec_test(violations, confidence_level, significance=0.05):
    """
    Perform Kupiec (Proportion of Failures) test
    
    Parameters:
    -----------
    violations : array
        Binary violation indicators
    confidence_level : float
        VaR confidence level (e.g., 0.95)
    significance : float
        Test significance level (default 0.05)
    
    Returns:
    --------
    dict with test results
    """
    T = len(violations)
    x = violations.sum()
    p = 1 - confidence_level  # Expected violation rate
    
    # Empirical violation rate
    p_hat = x / T
    
    # Likelihood ratio test statistic
    if x == 0:
        lr_pof = -2 * (T * np.log(1 - p))
    elif x == T:
        lr_pof = -2 * (T * np.log(p))
    else:
        lr_pof = -2 * (x * np.log(p / p_hat) + (T - x) * np.log((1 - p) / (1 - p_hat)))
    
    # Critical value (chi-square with 1 degree of freedom)
    critical_value = stats.chi2.ppf(1 - significance, df=1)
    
    # P-value
    p_value = 1 - stats.chi2.cdf(lr_pof, df=1)
    
    # Decision
    reject = lr_pof > critical_value
    
    return {
        'test': 'Kupiec (POF)',
        'violations': int(x),
        'expected_violations': T * p,
        'violation_rate': p_hat,
        'expected_rate': p,
        'LR_statistic': lr_pof,
        'critical_value': critical_value,
        'p_value': p_value,
        'reject_H0': reject,
        'conclusion': 'Model REJECTED' if reject else 'Model ACCEPTED'
    }
